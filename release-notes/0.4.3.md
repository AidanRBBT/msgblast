# msgblast 0.4.3

This release brings the comparison workspace and local account connections together. These changes were prepared in the unsuccessful 0.3.0–0.4.2 release attempts; 0.2.2 remained the last published app. No downgrade is required.

## Ask once and compare your agents

Muse, ChatGPT, Claude, and Grok join your Messages agents in My agents. Select recipients, write one request, and use Send & compare to see their conversations side by side. The four built-in agents start selected, and your selection is remembered.

- ChatGPT and Claude use native conversation panes through your local Codex and Claude Code accounts. Their replies, drafts, and provider sessions are saved with the comparison. These connections require the corresponding installed, signed-in command-line tool; a website login alone does not connect them.
- Muse and Grok stay inside embedded browser panes with persistent sign-in sessions. Sign in inside msgblast once for each service; Safari, Chrome, and standalone app sessions are separate.
- Muse uses your account's avatar when available, with its default image as a fallback. The app now captures avatars on Macs and build environments where GPU-backed image readback is unavailable.
- Local account settings provide sign-in for ChatGPT and Claude and detection/setup for OpenClaw and Hermes. Official command-line sign-in or setup continues in Terminal.

## Keep each Blast together

Each new Blast uses a dedicated conversation for each selected agent. Muse receives requests in a side chat instead of its main chat. Follow-ups continue in the same conversations, and saved comparisons restore their browser destinations or native provider sessions.

New Blast uses a compose icon and a compact toolbar position. Add Agent has a visible label. The window opens with more space for comparisons while staying within the display.

## Sign in without losing your request

If a selected account needs setup, the first shared request opens the account panes and explains how to sign in. Your request stays in the shared composer. After setup, press Send & compare again; signing in never submits it automatically.

Existing website drafts are preserved. Web sends wait for the intended conversation and Send control, save submission intent, then check for the outgoing message. Grok follow-ups recognize the saved conversation even when its response identifier changes. Interrupted or unconfirmed sends are not retried automatically.

## Less noise while comparing

Successful sends no longer repeat your prompt under an Appeared in… banner. Sending progress, failures, and unconfirmed results remain visible when action is needed. Temporary sign-in or dialog warnings clear when the conversation becomes ready. Redundant Open buttons and Needs attention badges are removed.

## Version, updates, and compatibility

- About and Updates display the version and build from the installed app. The signed update feed and fixed download link advance only after publication succeeds.
- macOS Sequoia 15 remains the minimum supported version, for both Apple Silicon and Intel. The clearer Messages connection prompt from 0.2.2 is retained.
- The production app uses the saved green icon; development and demo artwork remain separate.
- The repository is licensed under GPLv3. Separately licensed dependencies and artwork retain their own terms.

## Current limits

Shared requests involving Muse, ChatGPT, Claude, or Grok are text-only. Messages-only workflows retain attachment support. Service accounts and installed local tools have their own access requirements. Website changes can affect Muse/Grok submission; their embedded pages remain available for direct use. Seeing an outgoing message in a website confirms its appearance in that conversation, not a server delivery acknowledgement.

The app does not provide a shared automatic model or thinking-level selector. This release is ad-hoc signed and Sparkle-authenticated, without Apple notarization. Publishing an update does not install it automatically in every existing app copy.
