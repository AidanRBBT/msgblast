# msgblast 0.5.0

## Website chats by default, optional CLI agents

ChatGPT and Claude now open their websites inside msgblast, alongside Muse and Grok. Sign in within each pane; msgblast preserves its own browser sessions. The four website agents start selected on a new installation.

Enable **Codex CLI** or **Claude Code** in Settings to add each as an additional agent. You can send one blast to a website and its CLI side by side. Enabling a CLI does not replace its website; each keeps its own saved conversation, draft, and follow-ups.

Existing website sign-ins and saved chat URLs are retained. Previous native ChatGPT and Claude history moves to the separate Codex CLI and Claude Code entries, with backups of the original state. CLI entries are initially off. Disabling one later preserves its saved history and excludes it from new sends; turn it on in Settings to continue an archived CLI conversation.

## Clearer account status

- Connected Codex CLI and Claude Code accounts now offer **Switch account** in Settings instead of asking you to sign in again. Connected chat columns no longer show account status or account-management buttons.
- Empty connected chats explain that your message is ready to send. Refreshing account status keeps the request in the message box until you press Send.

## Account settings in one place

- **Your local accounts** now appears only in **Settings**, keeping Agents and comparison reports focused on conversations.
- ChatGPT, Claude, OpenClaw and Hermes use their official app artwork in account settings.
- Account setup and switching stay unavailable while a message or comparison report is being generated.

## Comparison navigation

- **My agents** is now **Agents**, including the labels in Discover.
- Starting or reopening a blast highlights its active comparison in the sidebar. New Blast returns the highlight to Agents.

Open **msgblast → Settings** (Command-comma) to manage your accounts.

## Current limits

Website and CLI sign-ins are separate. The CLI adapters remain text-only and do not yet run configured skills or connectors. Shared website/CLI requests require text; Messages-only conversations retain attachments. Website layout changes can affect submission, and unconfirmed sends are never automatically retried.

macOS Sequoia 15 remains supported. Production uses the green app icon; development builds use blue-green. This release uses the existing ad-hoc signing and authenticated Sparkle update path.
