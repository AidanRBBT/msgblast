# MsgBlast onboarding concept

This contact sheet is a generated design concept, not captured app screens or verified permission evidence. It uses fictional names and an example-domain account. No live contacts, chat history, or privacy settings were used or changed.

The six screens stage consent when its capability is used: Messages history setup; the user enabling Full Disk Access in System Settings; Contacts consent during Add; pinned recipient selection; Automation consent on the first actual send; and the connected comparison window.

The draggable icon represents the installed MsgBlast `.app` file URL. Dropping it in the Full Disk Access list cannot grant access. The person must enable the switch and may need to authenticate or restart. The illustrated success state means the app successfully read Messages history after that action, not merely that a drop completed.

The current app has an Open Full Disk Access and Check again card. The draggable app representation and illustrated journey are proposed UI. Native System Settings and consent dialogs here are illustrative; their exact wording/layout comes from macOS and cannot be restyled by MsgBlast.

The unknown account may be saved as a real Contacts entry independently of having an eligible chat. It remains unavailable for sending until an eligible existing conversation is present. The concept's Flint indicator is only a proposed unavailable presentation. The Contacts ID remains internal metadata.

Selected names are always visible. The compose grid defaults all available recipients to selected. The comparison has one shared editor and individually named pills; blue pills receive the next universal message, gray pills are excluded. The plus in the top toolbar adds an agent, while the plus beside the editor adds an attachment.
